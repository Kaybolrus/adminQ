# Admin Desk

Минималистичное настольное WPF-приложение для системного администратора Windows:
список устройств с мониторингом доступности, быстрый запуск RDP и полезные сетевые папки.

## Технологии

- C#, WPF, .NET 8 (net8.0-windows)
- Хранение данных: локальный JSON в `%AppData%\AdminDesk\data.json` (без SQLite, без серверов)
- Сторонние библиотеки не используются (только стандартная библиотека .NET)
- Приложение работает без прав администратора (`app.manifest` — `asInvoker`)

## Сборка и запуск (Windows, PowerShell)

Требуется установленный [.NET SDK 8](https://dotnet.microsoft.com/download/dotnet/8.0).

```powershell
cd AdminDesk

dotnet --info                       # проверка окружения (должен быть SDK 8.x)
dotnet restore AdminDesk.csproj
dotnet build AdminDesk.csproj -c Release
dotnet run --project AdminDesk.csproj -c Release
```

## Логические автотесты (кроссплатформенные)

Тесты проверяют DataService (сохранение/бэкап/восстановление), Validation и Monitor
без запуска GUI. Можно выполнять на Windows и Linux:

```powershell
cd AdminDesk
dotnet run --project Tests -c Release
# Ожидаемый результат: ИТОГ: 37 пройдено, 0 провалено.
```

## Публикация в EXE (Windows)

Файловая публикация (один exe, требует .NET Desktop Runtime 8 на целевом ПК):

```powershell
cd AdminDesk
dotnet publish AdminDesk.csproj -c Release -r win-x64 --self-contained false `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
# Результат: bin\Release\net8.0-windows\win-x64\publish\AdminDesk.exe
```

Автономная публикация (не требует установленного .NET, размер ~150 МБ):

```powershell
dotnet publish AdminDesk.csproj -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```

## Данные приложения

- Файл: `%AppData%\AdminDesk\data.json`
- Резервная копия: `%AppData%\AdminDesk\data.backup.json` (обновляется при каждой успешной записи)
- При повреждении `data.json`:
  1. повреждённый файл сохраняется как `data.json.damaged-<дата-время>`;
  2. данные восстанавливаются из `data.backup.json`;
  3. если копии нет — приложение открывается в режиме «только чтение»
     с записями по умолчанию, а запись на диск блокируется до подтверждения пользователя.
- При аварийных ошибках в `%AppData%\AdminDesk\error.log` пишется краткая информация.

## Функциональность

### Устройства
- Стартовая запись: **alttest10**, `192.168.10.66`, компьютер, RDP включён, мониторинг включён.
- Хранятся: имя, адрес (IP или DNS), тип, описание, флаг мониторинга, способ проверки
  (Ping / Ping+TCP-порт), флаг разрешения RDP.
- Добавление/редактирование/удаление через формы; валидация: пустые имя/адрес запрещены,
  IPv4 проверяется по октетам (0–255), TCP-порт — 1–65535, дубликаты имён запрещены.

### Кнопка RDP
- Запускает `mstsc.exe` с аргументом `/v:<адрес>` через `ProcessStartInfo.ArgumentList`
  (значения передаются как отдельные аргументы, shell/cmd.exe не используется).
- Адрес повторно валидируется перед запуском; пароли не запрашиваются и не хранятся.
- Доступность RDP-сервиса проверяет сам mstsc.exe — приложение этого не гарантирует.

### Полезные папки
- Стартовые записи: Установщики программ `\\DS2\FS-1\install`, Общие файлы `\\DS2\FS-1`,
  Рабочие файлы `\\DS2\RAM`, Сканирование `\\DS2\Scan`.
- Открытие в Проводнике Windows напрямую (`explorer.exe <путь>`, без shell-interpretации);
  перед открытием проверяется существование пути, при недоступности — понятное сообщение.
- Поддерживается перемещение карточек вверх/вниз (порядок сохраняется в JSON).

### Мониторинг доступности
- Цикл каждые 60 секунд; первая проверка — сразу после запуска.
- Асинхронно, UI не блокируется; ограничение одновременных проверок (семафор, максимум 8)
  и защита от повторного запуска проверки одного устройства (гейт на устройство).
- Тайм-ауты: Ping 2 с, TCP 3 с. Статусы: «Доступен», «Нет ответа», «Проверка», «Не проверялся».
- Проверяются только устройства с включённым мониторингом. Если Ping фильтруется сетью,
  используйте способ проверки «Ping + TCP» с нужным портом (например, 3389 или 445).
- При закрытии приложения цикл останавливается и текущие проверки отменяются.
- Мониторинг работает только пока приложение запущено (служба Windows не создаётся).

## Безопасность

- Работа без прав администратора; входящие порты не открываются, сервер не запускается.
- Произвольные команды/скрипты не выполняются; пользовательские значения попадают
  только в `ArgumentList` конкретных исполняемых файлов (`mstsc.exe`, `explorer.exe`).
- Ввод проходит валидацию; адрес устройства дополнительно проверяется перед запуском RDP.
- Пароли и секреты нигде не хранятся.
- Ошибки обрабатываются с уведомлением пользователя; молчаливое подавление исключений
  не применяется (журнал — `error.log`).

## Чего НЕ хватает / известные ограничения

- Поиск выполняет регистронезависимую фильтрацию по подстроке; для тысяч записей
  может потребоваться виртуализация списка.
- Ping на некоторых сетях недоступен без привилегий — это ожидаемо, используйте TCP-проверку.
- Изменение порядка папок — кнопками вверх/вниз (drag-and-drop не реализован).
- GUI-поведение (карточки, диалоги, адаптивность окна) требует финальной ручной
  проверки на Windows — сборка и логика проверены автоматически, но визуальная часть
  тестировалась только компилятором.
